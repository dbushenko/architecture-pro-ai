# 1. Сравнение LLM-моделей
## Локальные модели (Hugging Face)
Примеры: Llama 3.1 8B, Mistral 7B, BERT, T5
Качество ответов: Хорошее для специфических задач, можно дообучать под домен. Требуют тонкой настройки для достижения уровня GPT-4.
Скорость работы: Зависит от железа. На CPU - медленно (секунды на ответ), на GPU - быстрее.

Стоимость:

- Разовые затраты на сервер с GPU: $3,000-$10,000
- Энергопотребление: $100-$500/месяц
- Нет токен-based оплаты

Удобство развёртывания: Сложно, нужны ML-инженеры, CUDA, оптимизация

## Облачные модели (OpenAI / YandexGPT)
Примеры: GPT-4, Qwen, Deepseek, YandexGPT Pro
Качество ответов: Высокое, state-of-the-art для большинства задач
Скорость работы: Быстро (200-500ms), стабильная SLA

Стоимость:

- GPT-4: ~$0.03/1K токенов output
- GPT-3.5: ~$0.0015/1K токенов output
- При 1000 запросов/день: $500-$1000/месяц

Удобство развёртывания: Просто, API, минимум инфраструктуры

Вывод для QuantumForge: Для внутреннего бота с ~18K документов и конфиденциальными данными локальное решение безопаснее, но дороже в в развертывании.

# 2. Сравнение моделей эмбеддингов
## Локальные (Sentence-Transformers)
Модели: all-MiniLM-L6-v2, multilingual-e5-large
Скорость индексации:

18K документов (~21M токенов): 2-4 часа на CPU, 30-60 мин на GPU
Качество поиска: Хорошо для английского, хуже для мультиязычных
Стоимость: Бесплатно, только инфраструктура
Плюсы: Полный контроль, данные не уходят

## Облачные (OpenAI Embeddings)
Модели: text-embedding-3-small/large
Скорость индексации: Быстро, но ограничено rate limit-ами
Качество поиска: Лучшее на рынке
Стоимость:

text-embedding-3-small: $0.02/1M токенов

Для 18K доков: ~$0.5 за индексацию
Минусы: Данные уходят в облако

Вывод: Для мультиязычной документации (русский/китайский/английский) лучше OpenAI или специальные multilingual модели.

# 3. Сравнение векторных баз
## FAISS (Facebook AI Similarity Search)
Скорость поиска: Очень быстрая, оптимизирована для CPU/GPU
Скорость индексации: Быстрая
Сложность внедрения: Средняя, Python-библиотека
Удобство: Только векторный поиск, нужна отдельная БД для метаданных
Стоимость: Бесплатно, open-source
Поддержка: Сообщество + Meta

## ChromaDB
Скорость поиска: Хорошая, но медленнее FAISS на больших объемах
Скорость индексации: Средняя
Сложность внедрения: Простая, встроенная БД, есть persistence
Удобство: Все в одном - векторы + метаданные, фильтрация
Стоимость: Бесплатно, open-source
Поддержка: Активная разработка

Вывод: ChromaDB проще для начального развёртывания, FAISS - для продакшена с оптимизацией.

# 4. Рекомендуемая конфигурация сервера
Для локального развёртывания с учетом:

- 18K документов (~21M токенов)
- Онлайн-обслуживание 50+ concurrent пользователей
- Обновление индекса раз в неделю

## Вариант 1 (CPU-Only):

- CPU: 16 ядер (AMD EPYC или Intel Xeon)
- RAM: 64GB DDR4
- Storage: 1TB NVMe SSD
- GPU: Нет

Стоимость: $200-300/месяц (cloud), $3,000 (on-prem)

## Вариант 2 (С GPU для инференса):

- CPU: 8 ядер
- RAM: 32GB
- GPU: NVIDIA RTX 4090 (24GB) или A10G (24GB)
- Storage: 500GB NVMe

Стоимость: $1,000-1,500/месяц (cloud), $5,000 (on-prem)

## Вариант 3 (Гибридный):

- CPU сервер для эмбеддингов + FAISS: 16 ядер, 64GB RAM
- OpenAI API для LLM

Стоимость: $300 + API costs (~$500-1000)

## Итоговые рекомендации для QuantumForge
### Вариант A: Полностью локальный (макс. безопасность)
LLM: Llama 3.1 8B (инференс на GPU)

- Эмбеддинги: multilingual-e5-large (локально)
- Векторная БД: FAISS + PostgreSQL для метаданных
- Инфраструктура: Вариант 2 (GPU сервер)

Плюсы: Данные никогда не покидают инфраструктуру, нет ежемесячных API costs

Минусы: Высокие начальные затраты, нужен ML-инженер, качество ниже чем у GPT-4

Оценка стоимости: $8,000 капекс + $300/месяц опекс

### Вариант B: Гибридный (баланс цена/качество)
LLM: GPT-4 через Azure Private Endpoint

- Эмбеддинги: text-embedding-3-small (OpenAI)
- Векторная БД: ChromaDB (локально)
- Инфраструктура: Вариант 1 (CPU сервер)

Плюсы: Лучшее качество ответов, быстрый старт, данные защищены через private endpoint

Минусы: Зависимость от провайдера, monthly costs

Оценка стоимости: $200/месяц инфраструктура + $500-1000/месяц API

### Вариант C: Облачный SaaS (минимальные трудозатраты)
Полностью: Azure AI Search + OpenAI

Плюсы: Развёртывание за дни, масштабирование, enterprise SLA

Минусы: Самый дорогой, данные в облаке

Оценка стоимости: $2,000-5,000/месяц

### Вариант D: Компромиссный для старта
LLM: GPT-3.5-turbo (дешевле GPT-4 на 20x)

- Эмбеддинги: all-MiniLM-L6-v2 (локально)
- Векторная БД: ChromaDB
- Инфраструктура: 8 ядер CPU, 32GB RAM

Плюсы: Низкие costs, быстрое развёртывание

Минусы: GPT-3.5 хуже для сложных вопросов

Оценка: $100/месяц инфра + $200/месяц API

### Рекомендация
Выбираю Вариант B (Гибридный) для QuantumForge по причинам:

Безопасность: Конфиденциальные данные (промышленные digital twins, SCADA) через Azure Private Endpoint не уходят в публичный интернет

Качество: GPT-4 даст лучшие ответы чем локальные модели, что критично для сложных технических вопросов

Стоимость: Приемлемая для компании с оборотом ~$10M+, ROI за счет сокращения 4 часов/неделю поиска у 100+ инженеров

Скорость внедрения: Можно запустить MVP за 2-4 недели

Масштабируемость: Легко перейти на локальные модели когда они улучшатся

### Для векторной БД выбираю ChromaDB потому что:

Встроенное хранение метаданных (source, author, date)

Простая фильтрация по пространствам Confluence, типам документов

Персистентность из коробки

Хорошо интегрируется с LangChain

Для 18K документов производительности достаточно

Для MVP можно начать с Варианта D, а после валидации гипотезы перейти на Вариант B с GPT-4.
